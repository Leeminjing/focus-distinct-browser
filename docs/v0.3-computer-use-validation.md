# v0.3.2 Computer Use 验收 · 2026-10-24

本轮按用户要求修复 Computer Use 启动错误，再使用 `@oai/sky` 对已经运行的独立演示窗口进行桌面自动化验收。**这不是物理设备验收，没有把任何物理键鼠、触摸或跨屏项目记为通过。**

被测源码为 `8837b4f40a8aac875ebb800fd119a8c9a906c9fa`；使用 v0.3.2 发布目录中的 EXE，SHA-256 为 `a9689e052968479c7f8acbb96e968a7b6b2610a560161f6d80cef409e0dfb001`。本轮未改浏览器实现或固定产物，也未更新 Focus 或开发 v0.4。

## Computer Use 启动修复

最小 `node_repl` 文本输出在导入 Computer Use 前就报错 `failed to write kernel assets: 系统找不到指定的路径。(os error 3)`；重置会话仍失败。

检查确认临时根目录可写，Node 与 node_repl 运行文件存在。同一运行文件在新诊断进程能正常执行文本输出，因此继续检查本会话的常驻进程。该进程仍持有一个已经不存在的 `%TEMP%/.tmp…` 资源目录路径。仅补回它引用的目录后，原工具立即恢复，继而成功导入 `@oai/sky`、枚举窗口、截图并执行输入。

没有修改厂商运行文件、插件配置或安全设置，没有重启其他任务的进程。未确定是谁移除了目录；也未修改厂商代码来永久防止再次发生。因此这是当前会话运行环境的恢复，不宣称已修复上游目录生命周期问题。

## 本轮通过的桌面自动化检查

所有输入均通过 Computer Use JS API 操作指定的 `Collaboration A/B` 原生窗口，没有通过终端 UI 执行命令，没有操作其他 Focus 窗口。

| 检查 | 直接观察到的结果 |
| --- | --- |
| 首次按键接管 | 先以桌面点击确认网页输入框焦点，再交还至 Agent 状态；直接按 `n`，候选窗出现，A 转人工 |
| 当前系统中文 IME | 逐键输入 `n`、`i`，候选窗显示拼音；空格提交“你”；再输入 `z` 并按 Escape，取消组合且保留“你” |
| 接管后停止覆盖 | A 人工输入框完整内容在后续观察中保持不变，长度为 1207；无后续点号覆盖 |
| 地址快捷键 | Ctrl+L、Alt+D 选择原生地址栏；Escape 返回原页面，已提交中文保留，后续输入正常 |
| 自动期间跨视口拖拽 | A 的 Agent 恢复后，从原输入框拖到工具栏释放，选区保留且进入人工；页面记录释放 y=-24.6667、buttons=0；输入 `R` 替换整个选区 |
| 拖拽后的下一次点击 | 原页面计数器从 0 变成 1，无粘连捕获 |
| Ctrl+R、Tab / Shift+Tab | 同一窗口重载本地页面；Tab 依次到输入框、按钮，Shift+Tab 返回输入框 |
| 交还和 F5 | 交还后观察到 Agent 再次写入点号；自动期间按 F5，再次转人工并刷新原页面 |
| 首次滚轮接管 | 自动期间滚轮操作使页面实际 scrollY=400，状态转人工 |
| B 的独立运行 | A 人工期间 B 保持 Agent 状态，输入长度从 1362 增至 1964 |

IME 检查使用实际拼音按键和当前系统候选窗，不是用 `type_text("你")` 代替拼音组合；但输入仍由自动化注入，未核对输入法产品及版本，不能据此宣称物理设备 IME 验收通过。

初次仅激活窗口的按键探测没有确认网页原生焦点，因此没有据它判定首键结果；正式检查采用先点击输入框再交还的前提。一次工具操作因检测到外部输入而被拒绝，重新观察后才重试。即时 UIA 文本偶尔落后于截图，结论使用稳定后的观察；这些现象未被当作浏览器功能缺陷。

本轮没有独立读取演示客户端内存中的协议事件或令牌错误；旧令牌拒绝的协议证明仍以已有集成与稳定性回归为准。以上表格仅记录 Computer Use 直接看到的行为。
