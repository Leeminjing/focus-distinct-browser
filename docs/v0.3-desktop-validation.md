# v0.3.1 桌面输入验收 · 2026-10-24

这是 v0.3.1 的历史记录。后续 UI 停顿问题、独立钩子线程修复及当前人工入口见 [v0.3.2 稳定性记录](v0.3-stability-validation.md)，不将下文的短时桌面通过解释为长期稳定性通过。

基线为 `ee9495d` 的 v0.3.0。Windows 11 build 26200、WebView2 Runtime 155.0.4283.62、144 DPI；使用真实宿主 / WebView2 和 Windows SendInput，未用页面脚本触发输入或点击。

## 发现与修复

1. **首次字母已输入，但旧令牌仍有效。** 宿主队列、线程级探针和输入窗口探针只收到抬起，未收到首次按下。仅依靠 AllowHostInputProcessing 的预期不成立。补充 `WH_KEYBOARD_LL`，在系统派发原按键前先清除网页租约，状态绘制与协议通知延后到 UI 消息；原字符继续原生输入路径，不重新用 CDP 输入。
2. **快捷键漏接，处理 Alt 组合后可能被系统菜单抢走输入。** 自有窗口快捷键由保护层捕获，投递给同一 NativeToolbar 执行；消费已处理快捷键的按下 / 抬起和重复按下，避免宿主与内核双执行。对已处理的 Alt 快捷键抑制后续 SC_KEYMENU，不影响普通系统菜单入口。
3. **拖出网页视口后丢失抬键。** 前台网页原生左键按下派发后，由其输入代理保持 SetCapture；原始抬起派发后 ReleaseCapture，保持原选区及释放语义。

测试本身也修正了输入坐标与扫描码：CSS clientWidth 不含滚动条，不能用它除 HWND 宽度作为屏幕缩放比例；新建页面默认 zoom=1，按实际窗口 DPI 映射并读取最新窗口坐标。方向键使用扩展扫描码，避免测试把 Alt+Left 发成 Alt+NumPad4。移动与按下 / 抬起批量发送，交还前等待实际 pointerup，降低测试自身时序干扰。

## 通过的桌面检查

| 检查 | 实际证据 |
| --- | --- |
| 首次系统鼠标点击 | 原页面计数器增加，状态转人工，旧令牌拒绝 |
| 已有网页焦点时的首次键盘输入 | 原输入框得到字母，旧令牌立即失效，未依赖再点击网页 |
| Ctrl+L、Alt+D | 原生地址框聚焦并选择地址，后续 Enter 可导航 |
| Ctrl+R、F5 | 真实页面重新加载；包括重复 F5 按下，只产生一次重载 |
| Alt+Left / Alt+Right | 原浏览器历史前进后退，URL 与页面对应 |
| Tab / Shift+Tab | DOM 焦点按序移动，自动控制被撤销 |
| 拖拽、跨视口释放与后续操作 | 拖选 10 个字符，移到视口上方工具栏再抬起；DOM pointerup 的 y<0、buttons=0，选区为 [0,10]，随后输入替换选区，再次点击计数器正常 |
| 滚轮 | 原页面实际滚动，旧令牌失效 |
| 其他进程隔离 | 测试自己的原生组件进程接收系统 Unicode 输入，后台 A 的租约仍可续期 |
| 独立浏览器隔离 | 原生按键接管 A 后，B 仍能自动点击并产生 DOM 效果 |

入口：`python tests/desktop_input.py --run build/distinct-browser.exe`。套件输出 8 组 PASS，并生成 `artifacts/desktop-validation.json`，包含被测 EXE SHA-256、实际 Runtime、DPI、Windows build、时间、覆盖项与未验收项。发布包中的报告必须与 EXE 摘要匹配，打包脚本会检查。

曾尝试临时 Windows 桌面，但当前会话在该桌面无法读取输入位置；最终验收在当前交互桌面运行，仅对测试自有窗口发送输入。前台激活辅助临时关联测试线程与前台输入队列，随后立即解除；不是修改宿主的运行时前台策略。

## 键盘保护的实现取舍

这次新增的是**系统层全局低级键盘钩子**，并非线程钩子，也不能继续承诺“完全没有全局钩子”。它先核对前台窗口和焦点属于宿主，再读取按键；其他应用直接放行，不保存其按键。只有网页焦点下的输入撤销网页租约；自有工具栏快捷键仍按原有控制逻辑执行。没有全局鼠标钩子、生产网页输入监听器或外部分发依赖。

保护回调只改内存状态、投递消息，不执行 COM、绘制或管道写入；退出时卸载，安装失败则宿主启动失败。仍依赖 Windows 低级钩子与宿主 UI 消息泵；未专项压测长时间 UI 阻塞或钩子超时移除。它将作用于自有网页的系统输入视为人工意图，包括辅助输入或 SendInput；不会把宿主自己的 CDP 动作当作该类输入。

## 未验证项目

- 物理键盘、鼠标及具体驱动：本轮通过的是系统输入注入。
- 实际中文 IME 组合、候选窗、候选确认、取消与定位；已有 Unicode / IME 消息保护测试不能代替它们。
- 触摸 / 笔设备、笔悬停、压感及真实设备拖动。
- 不同 DPI 显示器之间的真实拖动；96 / 144 DPI 组件测试只验证布局和绘制。
- 不同 Runtime / 系统策略组合及长时间 UI 阻塞条件。
