# v0.3.2 稳定性与人工验收准备

本轮只收尾 v0.3，不开发 v0.4，不更新 Focus。v0.3.2 仍为待真实设备验收的候选版本。

## 已复现的问题与修复

在 `f15d6e7` 的 EXE 上，`python tests/keyboard_stability.py --run` 的最小复现连续失败两次：

1. 先验证普通首次按键接管成功。
2. 仅暂停测试自己创建的宿主 UI 线程两秒，期间向它的前台输入框发送系统按键。
3. 恢复线程后，原输入框收到字符，但旧租约仍可成功观察；再等 300 ms 排空通知仍如此，焦点也仍属于原页面。

这证实 UI 停顿会使当前接管路径失效，现象符合微软描述的低级钩子超时行为。Windows 不提供钩子被静默移除的通知，因此未声称读取到了“已移除”的系统状态。这是可控消息泵停顿实验，不等于已经在普通使用中测得两秒 UI 卡顿。

`KeyboardGuard` 改为独立原生消息线程安装、处理和卸载钩子。它通过只读窗口列表与 `GetGUIThreadInfo` 核对本宿主的前台焦点，不访问 UI 所有的 Browser、Control 或 COM 对象。网页输入意图先设置每浏览器的原子撤权标记，再放行原始输入；UI 在请求入口、动作派发、操作收尾及定时检查中消化标记，撤销既有令牌。即使 RPC 提交早于通知，恢复后也不能继续使用旧令牌。

浏览器快捷键仍消费已处理的按下 / 抬起并由 UI 执行，Alt 系统菜单抑制改用原子状态。普通字符不重放、不改写。窗口注销先标记失效并从钩子列表移除，线程退出时卸载钩子。

## 自动检查及边界

```powershell
python tests/keyboard_stability.py --run --cycles 20 --idle-seconds 60
python tests/desktop_input.py --run
./scripts/test.ps1
```

第一项生成 `artifacts/keyboard-stability.json`，包含 EXE SHA-256、实际持续时长、UI 停顿长度、循环和空闲时长；第二项生成 `artifacts/desktop-validation.json`。不要与其他桌面任务并行。

本机 Windows 11 build 26200 / WebView2 Runtime 155.0.4283.62 / 144 DPI 已通过上述参数的稳定性检查（实际 69.22 秒）、8 组桌面输入检查、38 项标准回归及 CMake 构建 / CTest。证据属于本地 Windows 执行，不是 GitHub Actions 或独立测试者的真实设备验收。

稳定性检查覆盖两秒 UI 停顿期间首次按键、此前提交的旧租约写入被拒绝、恢复后再次交还与首次按键、20 次交还 / 接管及 1000 个高频 Unicode 输入包、60 秒空闲与续期后的首次按键。高频部分使用 Unicode 包，避免当前 IME 把连续字母解释为拼音组合，**不能据此宣称真实 IME 已通过**。输入发生前已通过派发检查的操作仍可能收尾，不保证撤回网页副作用。

独立消息线程消除了本次复现的 UI 阻塞依赖；仍使用系统级全局低级键盘钩子。整个系统调度、其他软件钩子链和系统策略仍可能影响它，不能承诺永不超时或跨所有 Runtime 稳定。短时循环及空闲测试不能代替多小时真实设备使用。

## 人工验收入口

在桌面空闲时，由测试者从仓库目录运行：

```powershell
python demo/collaborate.py --typing --manual-report artifacts/manual-acceptance.json
```

程序创建两个本地测试页面，两个自动调用者每 0.7 秒向各自输入框写点号。测试者在 A 操作，观察 A 停止、B 继续；“交还”后 A 才恢复。程序不发送系统键鼠输入，不切换系统输入法或显示设置。网页只使用本地 fixture，不访问账号或外部网站。

终端会逐项提示以下七组检查，完成后填写 `pass`、`fail` 或 `skip` 加观察说明。无对应设备必须 `skip`；未填、失败或跳过的项目均列为 pending。Ctrl+C 会保留已填项目。报告注明 `human-reported`，包含 EXE 摘要、测试环境、逐项说明及最多 2000 条最近控制状态事件；不会把程序能启动当作真实设备通过。只在本地测试框输入验收文本。

| 项目 | 通过标准 |
| --- | --- |
| 物理首键 | 手动点进 A 输入框，再交还，等 Agent 点号出现后直接按字母；首字留在原框，旧控制资格被拒绝，A 不再追加点号，B 继续 |
| 物理点击 / 滚轮 | 交还后首次操作作用于原页面并接管；仅悬停、激活不接管 |
| 快捷键 / 设备拖拽 | Ctrl+L、Alt+D、Ctrl+R、F5、Tab、Shift+Tab 正常；拖选移至工具栏再释放，后续输入替换选区，无粘键；需导航时用本地 fixture 地址 |
| 中文 IME | 记录输入法和版本；从实际拼音组合开始接管，候选定位、选词、确认、取消、连续中文输入均正常，Agent 无后续覆盖 |
| 触摸 / 笔 | 首次接触、滑动、拖动保留效果并接管，笔悬停不接管 |
| 跨屏 DPI | 在不同缩放显示器间拖动；原生栏、点击坐标、IME 候选定位与页面输入正常 |
| 持续运行 | 至少一小时实际使用和反复交还后，首次按键仍接管；记录实际时长，不足时长不填 pass |

本轮没有物理设备或真实 IME 的人工通过记录。完成这些记录前，不将 v0.3 宣布为稳定版，不开始 v0.4；Focus 的真实 Run 与固定产物更新也留待后续验收。

参考：[微软 LowLevelKeyboardProc 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)说明安装线程需要消息泵、超时可静默移除，并建议使用专用线程。
