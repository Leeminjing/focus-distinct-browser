# v0.3 · Human–Agent Collaboration

本轮实现网页原生输入自动接管，保留 v0.2.1 外壳、独立数据目录和 JSONL v1。v0.3.1 已完成系统输入注入的桌面验收；v0.3.2 进一步修复 UI 停顿后键盘保护失效，使用独立消息线程和原子撤权标记。真实设备、IME 与跨屏 DPI 的人工验收尚未完成，仍按预发布交付。复现、修复及人工入口见 [稳定性记录](v0.3-stability-validation.md)。

## 行为

| 发生的情况 | 行为 |
| --- | --- |
| 直接点击、输入、滚轮、拖动或触摸 / 笔接触网页 | 在原始输入交给 WebView2 前撤销该浏览器令牌；同一次输入继续进入原页面 |
| 鼠标悬停、焦点变化、激活、`present` | 不接管 |
| CDP 点击、文字、按键或滚动 | 保持自动控制 |
| 有已派发操作 | 显示接管中；后续动作及未发子步骤拒绝，已发步骤如实结算 |
| 交还 | 开放新的租约申请、焦点回原页面，新调用者须先观察；旧操作不恢复 |
| 共享同一浏览器 | 当前令牌失效；其他调用者也须等交还和重新申请 |
| 另一个独立浏览器 | 不受此处接管影响 |

自动暂停只影响未来派发。已经发出的鼠标按下可能留下部分效果，原导航、网页脚本和网络请求也可以继续；接管不是撤销事务。

## 实现

`ICoreWebView2Environment10` 创建 ControllerOptions，`ICoreWebView2ControllerOptions4::put_AllowHostInputProcessing(TRUE)` 打开宿主输入处理，继续创建窗口化 Controller。构建 SDK 仍为 `1.0.3650.58`；该能力在稳定 SDK `1.0.3351.48` 引入，需要支持它的 Runtime（138+）。宿主检查 COM 接口和设置结果，缺少能力时创建失败并明确提示更新 Runtime。

每页增加一个不可见于布局外观的原生容器边界。消息循环按 HWND 子树定位浏览器，在 TranslateMessage / DispatchMessage 前调用既有控制权撤销。`src/window/page_input.h` 分类原生输入意图，租约及在途状态仍由 `src/control.h` 负责。v0.3.1 实测 Runtime 漏传首次字母按下后，增加按前台焦点过滤的 `WH_KEYBOARD_LL`；它在系统层是全局钩子，不能再声称完全不使用全局钩子。没有全局鼠标钩子或生产网页接管脚本。具体边界见 [桌面验收记录](v0.3-desktop-validation.md)。

启用输入处理后 AcceleratorKeyPressed 变成异步，因此不依赖该事件仲裁。v0.3.1 在原生键盘保护中捕获实际快捷键并延后交给既有 NativeToolbar；内部投递来自真实按键，不把向内部消息直接发参数的测试当作快捷键验收。Tab 通过 MoveFocus / MoveFocusRequested 在网页和原生控件间移动，保留原生 EDIT 的 IME 确认保护。

新增的协议语义只有既有 `control_changed` 事件中的 `detail.reason=human_input`。未增加 RPC，也未修改其他应用的映射逻辑。

## Windows 自动验证

标准入口：`scripts/build.ps1`、`scripts/test.ps1`。测试使用真实 EXE 与 WebView2；本机安装的稳定 Runtime 为 155 系列。

- `page-input-tests`：33 个 Win32 输入分类用例，包含鼠标、键盘、IME、触摸 / 笔接触、拖动，以及悬停、激活、单独修饰键、Alt+Tab 等不接管输入。
- `tests/collaboration.py`：向测试自己拥有的 WebView2 原生输入 HWND 投递消息；验证首次点击、按键、滚轮、拖动选字和 Unicode 的真实 DOM 效果，以及旧令牌失效、新租约重新观察、共享与跨浏览器隔离。
- 同一套测试检查网页 F5、网页内部 Tab 与原生工具栏边界；原有 v0.2 地址、历史、刷新 / 停止、主题、DPI 和控制回归继续运行。旧的测试专用内部快捷键消息已删除，不能再用它假称验证真实组合键。
- 慢导航期间介入：首次点击作用于仍可见的原文档，状态先接管中，导航未被假称撤回，返回真实导航结果后转人工。
- 多步点击交错：测试网页同步阻塞 pointerdown 处理，确保 CDP 按下在途；原生滚轮撤销租约，释放阻塞后返回 `invalid_token`，详情为 `dispatched_steps=1`、`completed_steps=1`、`result_unknown=true`。未发抬起不继续派发，滚轮随后真实滚动原页面。
- 原有独立 / 并行 / 共享、租约、导航结算、协议、数据隔离、断连与故障套件。

原生消息测试不等于物理键鼠或完整 IME 验收，也不证明指针设备和系统输入法的全部行为。

## 待补的桌面与人工验收

v0.3.0 阶段桌面套件未通过。其他桌面任务结束后，本轮重新执行并修复三项缺口，v0.3.1 的 8 组系统输入桌面测试全部通过。环境与逐项证据见 [桌面验收记录](v0.3-desktop-validation.md)，原始 JSON 报告随 v0.3.1 产物提供；该结果不能替代实际 IME 或物理设备验收。

桌面空闲后执行：

```powershell
python tests/desktop_input.py --run
python demo/collaborate.py
# 输入框保持焦点，验证首次键盘和 IME 介入：
python demo/collaborate.py --typing
```

桌面脚本会临时置顶并激活它自己的窗口、移动鼠标并发送系统输入；只在命中和前台窗口属于测试时继续，结束后关闭自己的窗口并恢复鼠标位置。它还打开自己的原生组件测试进程验证外部输入隔离；不对用户的其他应用发输入。不要与其他桌面自动化并行。系统注入与物理设备应分开记录。

| 待验项目 | 必须观察到的结果 |
| --- | --- |
| 首次物理点击、滚轮、键盘输入 | 首次效果保留在原页面，Agent 后续操作停止，旧令牌失效 |
| 输入框已有焦点时开始真实中文 IME 组合 / 候选确认 | 一开始就接管，组合及确认不丢失，Agent 不继续覆盖输入 |
| 物理组合键及实际设备拖拽 | 系统注入已覆盖 Ctrl+L、Alt+D、Ctrl+R、Alt+左右、F5、Tab / Shift+Tab 和跨视口释放；物理设备补验仍须保证单次执行、正确焦点和无粘键 |
| 触摸、笔接触 / 滑动，以及笔悬停 | 接触操作自动接管，首次内容效果保留；悬停不接管 |
| 同时操作两个浏览器，反复接管 / 交还 | A 接管不打断 B；交还后新控制者重新观察 |
| 跨 DPI 显示器拖动、真实 IME 候选窗 | 工具栏与输入坐标不漂移，候选窗位置正确 |

尚未用旧版 Runtime 实机运行缺少接口的创建失败分支。当前是能力检查实现与新 Runtime 上的运行验证，不能说所有 Runtime / 系统策略组合均已覆盖。
